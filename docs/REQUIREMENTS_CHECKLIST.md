# TeamFlow Requirements Verification Checklist

This document tracks all 11 mandatory assignment requirements and maps each requirement to its frontend pages, backend endpoints, and automated/manual tests. Each item is marked verified only after real testing.

| # | Requirement | Pages / Components | Backend Endpoints | Tests / Verification | Status |
|---|---|---|---|---|---|
| **1** | **Home page:** Authenticated home/dashboard with real project stats and recent activity. | `/dashboard`, `DashboardView`, `StatCard`, `ProjectHealthList`, `ActivityFeed` | `GET /api/dashboard` | `tests/dashboard.test.ts`, manual browser verification | ⏳ Pending (Phase 3) |
| **2** | **Listing and details:** List and detail pages for projects and issues (tasks and bugs). | `/projects`, `/projects/[id]`, `/issues`, `/issues/[id]`, `/bug-reports` | `GET /api/projects`, `GET /api/projects/:id`, `GET /api/issues`, `GET /api/issues/:id` | `tests/phase2.test.ts`, verified | ✅ Verified |
| **3** | **Create and update:** Create and edit projects, tasks, and bug reports. | `/projects` (modal), `/projects/[id]` (settings tab), `/issues/new`, `/bug-reports/new`, inline issue editors | `POST /api/projects`, `PATCH /api/projects/:id`, `POST /api/issues`, `PATCH /api/issues/:id`, `PATCH /api/issues/:id/status` | `tests/phase2.test.ts`, verified | ✅ Verified |
| **4** | **Delete:** Delete records user owns or is permitted to manage, with confirmation dialogs. | `ConfirmDialog` across projects, issues, comments, attachments | `DELETE /api/projects/:id`, `DELETE /api/issues/:id`, `DELETE /api/comments/:id`, `DELETE /api/attachments/:id` | `tests/phase2.test.ts`, verified | ✅ Verified |
| **5** | **Interaction:** Comments, issue discussion, assignments, status updates, and media attachments. | `CommentThread`, `StatusSelect`, `AssigneeSelect`, `MediaGallery` | `GET/POST /api/issues/:id/comments`, `PATCH/DELETE /api/comments/:id`, `PATCH /api/issues/:id/status`, `POST /api/issues/:id/attachments` | `tests/comments.test.ts`, `tests/attachments.test.ts` | ⏳ Pending (Phase 3 & 4) |
| **6** | **Search and filtering:** By title/desc, status, priority, assignee, reporter, project, type (backend executed). | `IssueFilterBar`, `SearchBar`, query sync to URL | `GET /api/issues?q=&status=&priority=&assigneeId=&projectId=&type=` | `tests/issues.test.ts` | ⏳ Pending (Phase 3) |
| **7** | **User profile:** User info, assigned tasks, reported issues, activity; editable own profile. | `/profile`, `/users/[id]`, `ProfileEditModal` | `GET /api/users/:id`, `PATCH /api/users/me`, `GET /api/users/:id/issues`, `GET /api/users/:id/activity` | `tests/users.test.ts` | ⏳ Pending (Phase 3) |
| **8** | **Backend API:** Functional REST endpoints connecting frontend to server-side logic. | Typed client (`client/lib/api.ts`) connecting to Express REST API | Standard `/api/*` endpoints with unified JSON error envelope | `tests/*.test.ts` Supertest suite | ⏳ Pending (Phase 1-4) |
| **9** | **Database:** Core records persisted in PostgreSQL and surviving refreshes and restarts. | All screens display DB state | Prisma ORM with committed migrations, normalized models | Migration verification, seed test | ⏳ Pending (Phase 1) |
| **10** | **Validation and error handling:** Invalid input, unauthorized operations, failed API calls, loading states. | Zod schemas, toast alerts, error boundaries, skeleton loaders, retry affordances | Centralized Express error handler, Zod body/query/param validation | Negative tests for 400, 401, 403, 404, 413, 415, 422 | ⏳ Pending (Phase 1-5) |
| **11** | **Responsive UI:** Works on desktop, tablet, and mobile. | Tailwind responsive grid, collapsible mobile drawer, touch-friendly Kanban status menu | Mobile-friendly API responses and pagination | Mobile browser testing at 375px, 768px, 1280px | ⏳ Pending (Phase 5) |
